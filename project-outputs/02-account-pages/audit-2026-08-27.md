Account Pages — Heuristic Audit

Date: 2026-08-27
Scope: Account area, all five tabs (Overzicht, Jouw profiel, Adressen, Betaalwijzen, Bestellingen). Source: project-inputs/Screenshots/acc.suprabazar.hosted-temp.com_account*.png
Method: Nielsen heuristic evaluation + account IA reference model + data visualization review
Additional input folded in: project-inputs/ux-improvements.md (already-agreed directions, not independently "discovered" here)

Summary

The account area is functionally complete for basic profile/address/payment management, but two things stand out: order information is presented as plain data rows with no visual status communication, and several account-area concepts the brand already promotes elsewhere (SupraKaart, digital gift cards, returns) are entirely absent from the account itself. This matches the direction already agreed in ux-improvements.md — the findings below give that direction a severity ranking and tie it to concrete screen elements.

Findings

Severity High

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Order status visualization | Bestellingen (and the "Laatste bestelling" card on Overzicht) show Leveringsstatus/Betalingsstatus as plain text ("Shipped", "Paid") with no color coding, icon, or progress stepper | Visibility of system status, Recognition rather than recall | Shopper must read every word to understand order state; no at-a-glance scanning across multiple orders |
| Order status source | Per ux-improvements.md, delivery status text is currently static/manual rather than synced to real carrier state (cancelled / shipped / delivered) | Match between system and real world | Status shown may not reflect reality, undermining trust in the account area entirely |
| Missing loyalty/SupraKaart integration | "SupraKaart" is a top-nav concept (visible in the header on every account page) but has no presence — balance, points, tier — anywhere inside the account area | Consistency and standards | Account area feels disconnected from a loyalty program the brand actively promotes; missed engagement/retention opportunity |
| Missing return request flow | No way to request a return from an order (Bestellingen only offers a "Tonen" expand and a "..." menu of unknown contents) | User control and freedom | Per ux-improvements.md this is an explicitly desired capability; today the shopper must leave the account area (email/phone) to request a return |
| Missing gift card management | No gift card balance or management anywhere in the account (not on Overzicht, not a dedicated tab), despite "Digitale cadeaubon" being a footer link | Match between system and real world | Shoppers holding a gift card have no way to check balance or pre-select it for future checkouts from their account |

Severity Medium

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Order summary depth | Order rows show only Leveringsstatus/Betalingsstatus/Betaalwijze/Leveringswijze — no order total, no line-item thumbnails, no item count, until "Tonen" is clicked | Visibility of system status | Shopper can't distinguish a €15 order from a €200 order without expanding each one; harder to spot the right order in a long history |
| Order history navigation | Bestellingen lists orders in a flat, unpaginated stack with no date-range filter, status filter, or search | Flexibility and efficiency of use | Fine for 2 orders (as shown); will not scale for a returning customer with a long history |
| "..." menu affordance | Each order card has an unlabeled "..." icon button with no visible tooltip/label in the screenshot | Recognition rather than recall | Unclear what actions live behind it (this is likely where "request a return" should surface) |
| Sidebar navigation | Five flat tabs (Overzicht, Jouw profiel, Adressen, Betaalwijzen, Bestellingen) with no icons, just text links, and "Overzicht" duplicates content shown on other tabs (address, payment) verbatim | Aesthetic and minimalist design | Overzicht is a redundant mirror of Adressen + Betaalwijzen instead of adding new information (e.g. it could carry the loyalty/order-summary role instead) |
| Newsletter checkbox placement | "Inschrijven op de nieuwsbrief" sits on the Overzicht tab, unrelated to "profiel information, betaalmethode and addresses" described in the tab's own intro line | Match between system and real world | Slightly mismatched content grouping; minor information-architecture inconsistency |

Severity Low

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Address management | Adressen page shows "Standaard factuuradres" / "Standaard afleveradres" and then repeats the same address a third time under "Alle adressen" with only one entry | Aesthetic and minimalist design | With only one saved address the triple repetition is redundant; will need a clearer list/card pattern once a shopper has multiple addresses |
| Payment method list | Betaalwijzen lists 6 payment options as a plain radio list with logos flush right; no visual grouping (e.g. cards vs. bank apps) | Aesthetic and minimalist design | Minor scanability issue, not a functional blocker |

What is already working well

- Profile edit form (Jouw profiel) has clear required-field marking and a visible "Velden gemarkeerd met asterisks zijn verplicht" note
- Standaard betaalwijze selection uses a simple, familiar radio-button pattern
- Order card layout (Bestelling: date, Bestelnummer, four-column status row) is consistent between Overzicht and Bestellingen — good reuse

Quick wins (prioritized)

1. Replace plain-text Leveringsstatus/Betalingsstatus with a color-coded stepper or badge (e.g. grey → blue "In verwerking" → yellow "Shipped" → green "Delivered", red "Cancelled") reused identically on Overzicht and Bestellingen
2. Sync that status to real delivery state per ux-improvements.md (data/integration work, not just UI — flag as a backend dependency)
3. Add an order total and item-count/thumbnail preview to each order row so it's scannable without expanding "Tonen"
4. Add a "Vraag retour aan" action on each eligible order (surfaced directly, not buried in the unlabeled "..." menu)
5. Add a SupraKaart balance/points summary to Overzicht (replacing some of its current redundancy with Adressen/Betaalwijzen)
6. Add gift card balance + management to the account area (new section or tab), with auto-selection at checkout as a follow-on

Note: items 2, 4, 5, 6 above were already directionally agreed before this audit (see project-inputs/ux-improvements.md); this audit adds severity ranking, ties them to specific screens, and adds items 1 and 3 as UI-only quick wins that don't require backend/data changes.

Update 2026-08-27: the Medium-severity "Newsletter checkbox placement" finding has been addressed in the prototype — the "Inschrijven op de nieuwsbrief" control was relocated from Overzicht to a new "Nieuwsbrief" section on Jouw profiel, grouped with the account's other login/profile preferences.
