Category Filters — Heuristic Audit

Date: 2026-08-27
Scope: Category overview page, "Puzzelen" (desktop, mobile overlay). Source: project-inputs/Screenshots/acc.suprabazar.hosted-temp.com_speelgoed_puzzelen*.png
Method: Nielsen heuristic evaluation + e-commerce facet/filter pattern benchmarking

Summary

The filter sidebar covers the basics (category tree, stock/promo toggles, brand list, price range, one sort control) but gives the shopper almost no feedback once a filter is touched: no live result count, no indicator of which filters are active, and a long brand list hidden behind a low-visibility "Toon meer" link. Mobile compresses the same limitations into a full-screen overlay, which raises the cost of trial-and-error even further.

Findings

Severity High

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Result feedback | Result count ("440 resultaten") only appears once, next to the page title, and does not visibly update as filters are toggled | Visibility of system status | Shopper can't tell if a filter combination is too narrow (0 results) or too broad before committing; encourages repeated trial clicks |
| Active filters | No "applied filters" chips/summary anywhere on the page. Once several checkboxes are ticked, there's no single place to see or clear them | Visibility of system status, User control and freedom | Shopper loses track of what's filtering the grid; the only way to check is to re-scan the whole sidebar |
| Brand list discoverability | Full brand list ("Merk") is a long checkbox list truncated behind a plain-text "Toon meer" link, no search-within-list, no count per brand | Recognition rather than recall | Shoppers looking for a specific, less-common brand (not in the first ~10) must click through and manually scan; no count means they can't judge relevance before clicking |

Severity Medium

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Sort control | Single sort dropdown ("Naam, A-Z") with no visible alternative context (e.g. price asc/desc, relevance, newest) until opened | Recognition rather than recall | Shoppers can't scan sort options at a glance; default sort (alphabetical) is rarely the most useful for product discovery vs. price or popularity |
| Filter-to-result connection | Checkbox filters (Op voorraad / In promotie / Vaste lage prijs) show no per-option result count (e.g. "Op voorraad (12)") | Visibility of system status | Shoppers can't judge which filter is worth applying without clicking it first |
| Price range | Min/Max free-text inputs with no visible slider, histogram, or step guidance | Match between system and real world | Harder to pick a meaningful range quickly compared to a slider with visible distribution |
| Mobile filter entry point | Mobile replaces the sidebar with a single "Filter" button; the sort dropdown is a separate, adjacent control of similar visual weight | Consistency and standards | Two competing controls (Filter vs. sort) with similar styling can be misread as one combined control |

Severity Low

| Area | Finding | Heuristic / pattern violated | Impact |
|---|---|---|---|
| Category tree | Flat list of 4 subcategories with no indication of item counts or current selection highlight beyond "Puzzelen" being on the current page | Visibility of system status | Minor — shopper can't gauge subcategory size before navigating |
| Wishlist affordance | Heart icon on each product card has no visible state change cue in the screenshot (filled vs outline) at a glance | Visibility of system status | Low confidence on whether an item is already wishlisted |

What is already working well

- Clear breadcrumb (Home > Speelgoed > Puzzelen)
- Stock and delivery-time messaging is present on every product card, not just filterable — supports purchase confidence
- Mobile filter overlay is a full-screen pattern (correct choice over a cramped inline panel) rather than a cramped inline panel

Quick wins (prioritized)

1. Add a live, updating result count next to the sort control (or at the top of the filter sidebar) that reflects the current filter state, including before/while a filter is being applied
2. Add an "applied filters" row of removable chips above the product grid, with a single "Clear all" action
3. Add per-option result counts to checkbox filters (stock/promo/price-tier and brand list)
4. Promote "Toon meer" to a search-within-brand-list input once the list exceeds ~10 items, so shoppers can type instead of scanning
5. Differentiate the mobile "Filter" button and sort dropdown visually (icon + outline vs filled, or grouped under one "Filter & sort" control) to avoid confusion
